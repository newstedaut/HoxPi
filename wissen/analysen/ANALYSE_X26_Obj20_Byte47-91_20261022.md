# X26 Obj 0x20 Byte 47-91: Zähler, Ansaugtemperatur, P_el – und die Regel „Byte n = Datenpunkt n“

## Kernbefund (sicher)
**Die Nutzbyte-Position im Obj 0x20 ist die Datenpunkt-Nummer der Funktion „FA Allgemein“ (fg 60 / fn 254)** aus `HoxPi-Doku\WEZ_Register_offiziell_UnitId1.csv`:
dp 21 Brennerflamme … dp 33 WEZ-Status, dp 45 COP, dp 47 Wärmemenge Heizen, dp 51 Kühlen, dp 55 WW, dp 84 Ansaugtemp., dp 85 Verdampferoberfläche – jeweils genau an Byte 21/33/45/47/51/55/84/85.
Die frühere Faustregel „Byte n = Reg 1507+n“ ist nur die Folge davon (Reg 1520… = dp 0…). Feldlängen laut Code-Tabelle: 4 Byte ab 47/51/55/59/63/67/71/75/79, je 1 Byte 83–89, 2 Byte 90–91.

## Was bringt uns das
- Alle Energiezähler (Heizen/WW/Kühlen/Strom), Stunden und Starts liegen im passiven 0,5-s-Mitschnitt – **Tages-Arbeitszahl getrennt nach Heizen und WW** direkt aus Zählerdifferenzen, ohne Modbus-Abfrage und ohne Integration.
- Mit der dp-Regel ist jedes weitere Byte über die offizielle Registerliste deutbar – kein Raten mehr pro Byte.
- Ansaugtemperatur (Byte 84) sekundengenau → Abtau-Erkennung und COP gegen Lufttemperatur möglich.
