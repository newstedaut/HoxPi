**Weg für unsere XML-Patches (ohne .loxl-Projekt):**
1. `lox config download --extract --save-as backups\<stamp>.zip` → Live-ZIP + .Loxone (Basis-Prüfung: `lox config diff <meine Basis> <live.Loxone>` muss „No logic changes" zeigen).
2. Patch-Skript wie bisher → NEU.Loxone; `lox config diff live.Loxone NEU.Loxone` = genau die gewollten Änderungen.
3. `lox config compress NEU.Loxone --template backups\<stamp>.zip --save-as backups\<stamp>-push.zip` (nur sps0.LoxCC ersetzt, byte-identisch verifiziert).
4. `lox config upload backups\<stamp>-push.zip --force` (listet vorher Custom Changes der App – Stimmungen/Timer/Regeln, die Config nicht gespeichert hat; die gehen beim Laden verloren, wie beim Speichern aus Config).
5. Laden: `lox reboot --yes` (voller Neustart ~1 min). Programm-Neustart ohne Reboot macht nur `lox config push` (braucht lox.toml-Projekt; Option `--patched-from <download.Loxone>` ist für Byte-Patches gedacht → als Nächstes testen, dann entfällt der Reboot).
6. Danach `lox config download --extract` und diff gegen NEU = Abnahme der Datei; Live-Werte wie gehabt.

**Zugang:** `lox setup set --host http://<LAN-IP> --user <Admin> --pass <PW>` und `lox setup set --serial <Seriennr>` – macht der Betreiber selbst (Passwort in `%USERPROFILE%\.lox\config.yaml` im Klartext, oder Umgebungsvariablen LOX_HOST/LOX_USER/LOX_PASS). Admin nötig, weil push/upload die Benutzerliste vergleicht. Empfehlung: eigener Benutzer „lox" mit Admin-Recht, dann steht im Protokoll, wer gespeichert hat.

**Regel bleibt:** Upload/Push nur mit des Betreibers Go je Umbau, nie aus einer geplanten Aufgabe; Backup-ZIP vor jedem Upload (`<stamp>-pre-push.zip` bzw. unser Download), Rückweg `lox config upload <backup>.zip --force && lox reboot --yes`.
